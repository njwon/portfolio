JS와 Node.js의 역사

JS는 본래 웹 페이지를 조작하는 동적인 페이지의 핵심 중추인 언어로써 웹 브라우저를 제외한 환경에서는 쓰지 않는 언어였다.
하지만 2008년 9월 JS의 초창기와 달리 빨라지고 강력한 C++를 기반으로 동작하는 V8 엔진이 등장하며, 웹 브라우저가 아닌 환경에서 사용할 수 있도록 하자는 의견이 많아졌고 이에 따라 CommonJS 표준이 발표되었다.
이 흐름에 힘입어 2009년, CommonJS 표준, V8엔진을 이용하여 non-blocking, evnet-driven I/O 패러다임에서 작업할 수 있는 Node.js가 탄생했다.

Express.js의 역사

20010년 처음 개발된 Express.js는 Node.js를 위한 웹 애플리케이션 프레임워크로, 서버 측에서의 개발을 간소화하고 효율적으로 할 수 있도록 설계되었다. 이 프레임워크는 RESTful API 및 웹 애플리케이션을 구축할 때 필요한 다양한 기능을 제공한다.
Express.js는 빠르고 유연한 구조를 가지고 있으며, 미들웨어를 통해 요청과 응답을 처리할 수 있는 강력한 기능을 지원한다. Express.js의 주요 특징 중 하나는 라우팅 기능으로, 사용자가 정의한 경로에 따라 요청을 적절한 핸들러로 전달할 수 있다. 이러한 특성 덕분에 Express.js는 대규모 애플리케이션 개발에도 적합하다. 또한, Express.js는 다양한 미들웨어와의 호환성이 뛰어나, 개발자들이 필요에 따라 추가 기능을 쉽게 통합할 수 있다. Express.js를 기반으로 한 애플리케이션 개발은 클라이언트와 서버 간의 효과적인 데이터 교환을 가능하게 하며, 이는 현대적인 웹 개발에 필수적인 요소가 되었다.

Express.js 설치

Express.js를 설치하기 위해서는 먼저 Node.js가 시스템에 설치되어 있어야 한다. Node.js는 JavaScript 런타임 환경으로, Express.js가 동작하는 기반이 된다. Node.js가 설치된 후, 명령 프롬프트나 터미널을 열고 아래의 명령어를 입력하여 Express.js를 설치할 수 있다. npm(Node Package Manager)을 사용하여 설치하는 방법은 다음과 같다. ‘npm install express’라는 명령어를 입력하면 Express.js가 프로젝트에 추가된다. 설치가 완료되면, 프로젝트의 기본 파일 구조를 설정해야 한다. 이를 위해 ‘index.js’라는 파일을 생성하고 다음과 같은 기본 코드를 작성할 수 있다.

const express = require('express')
const app = express()
const port = 3000

app.get('/', (req, res) => {
  res.send('Hello World!')
})

app.listen(port, () => {
  console.log(`Example app listening on port ${port}`)
})

코드 작성이 완료되면 node index.js 명령어를 실행해 서버가 열리는 것을 확인할 수 있다.

더 자세한 설명은 여기에서 확인 가능하다.

Express.js gen으로 애플리케이션 생성하기

express를 매번 설치하고 세팅해야하면 무척 힘들것이다.
그래서 express에선 generator를 제공한다.
'npm install -g express-generator' 명령어로 express-generator을 설치한다.
'express' 명령어를 통해 프로젝트를 생성할 수 있다.

사용법은 다음과 같다.

기본 명령어: express [옵션] [폴더이름]
Options (옵션):

-h, --help
output usage information
사용법 정보(도움말)를 출력한다.

--version
output the version number
버전 번호를 출력한다.

-e, --ejs
add ejs engine support
EJS 엔진 지원을 추가한다. (뷰 엔진으로 EJS 사용)

--hbs
add handlebars engine support
Handlebars 엔진 지원을 추가한다.

--pug
add pug engine support
Pug 엔진 지원을 추가한다.

-H, --hogan
add hogan.js engine support
Hogan.js 엔진 지원을 추가한다.

--no-view
generate without view engine
뷰 엔진 없이 생성한다. (HTML 파일 없이 서버 구조만 생성)

-v, --view <engine>
add view <engine> support (ejs|hbs|hjs|jade|pug|twig|vash) (defaults to jade)
특정 <뷰 엔진> 지원을 추가한다.
(선택 가능: ejs, hbs, hjs, jade, pug, twig, vash 중 하나 / 기본값은 jade)

-c, --css <engine>
add stylesheet <engine> support (less|stylus|compass|sass) (defaults to plain css)
특정 <스타일시트 엔진> 지원을 추가한다.
(선택 가능: less, stylus, compass, sass 중 하나 / 기본값은 일반 css)

--git
add .gitignore
.gitignore 파일을 추가한다. (Git 관리 제외 목록 파일 생성)

-f, --force
force on non-empty directory
비어있지 않은 디렉토리(폴더)에도 강제로 생성한다. (덮어쓰기)

generator에서 필요한 종속성을 설치한다.

cd myapp
npm install

다음 명령어를 실행해 서버를 실행한다.

macOS 또는 Linux에서 다음 명령어를 사용하여 앱을 실행.
$ DEBUG=myapp:* npm start
Windows 명령 프롬프트에서 다음 명령을 사용하여 앱을 실행.
set DEBUG=myapp:* & npm start
Windows PowerShell에서 다음 명령을 사용하여 앱을 실행.
PS> $env:DEBUG='myapp:*'; npm start

generator로 생성된 앱은 다음과 같은 디렉토리 구조를 가지게 된다.

.
├── app.js (핵심 설정 js 파일)
├── bin
│   └── www (서버 실행 파일)
├── package.json (설정 및 라이브러리 목록)
├── public (정적 파일 저장소)
│   ├── images
│   ├── javascripts
│   └── stylesheets
│       └── style.css
├── routes (컨트롤러)
│   ├── index.js
│   └── users.js
└── views (화면 템플릿)
    ├── error.pug
    ├── index.pug
    └── layout.pug
