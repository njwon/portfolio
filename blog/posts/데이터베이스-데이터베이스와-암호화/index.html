데이터베이스

한 번쯤 다이어리에 일정과 메모를 적고, 학교에서 들은 강의를 노트에 기록해 본 경험이 있을 것이다. 새로운 일정이 생기면 다이어리를 펼쳐 날짜에 맞게 기록하고, 일정이 변경되거나 취소된다면 기록한 내용을 수정하거나 삭제할 수 있다. 일상 생활에서 생기는 다양한 정보를 기록하기 위해 다이어리와 노트를 사용하듯이, 컴퓨터도 정보를 기록하기 위해 **데이터베이스(Database)**를 사용한다.

데이터베이스는 단순히 데이터를 쌓아두는 공간이 아니다. 현대 웹 서비스는 다양한 기능을 제공하는데, 예를 들어 어떤 사이트에 회원가입을 하고 로그인해 게시글을 쓸 수 있는 것도 웹 서버가 데이터베이스를 사용하여 회원 정보와 게시글을 저장하고 조회, 수정하기 때문이다. 다수의 사람들이 동시에 데이터를 생성하고 참조하고 수정하는 웹 서버의 특수한 환경에 가장 적합한 자료구조로 채택된 것이 데이터베이스이며, 최근의 웹 서비스에는 거의 필수적으로 포함된다.

DBMS

데이터베이스를 관리하는 애플리케이션을 **DBMS(DataBase Management System)**라고 한다. DBMS는 데이터베이스에 새로운 정보를 기록하거나, 기록된 내용을 수정, 삭제하는 역할을 한다. 다수의 사람이 동시에 데이터베이스에 접근할 수 있고, 웹 서비스의 검색 기능과 같이 복잡한 요구사항을 만족하는 데이터를 조회할 수 있다는 것이 DBMS의 핵심 특징이다.

DBMS는 크게 **관계형(Relational)**과 **비관계형(Non-Relational)**으로 분류된다. 관계형은 행과 열의 집합인 테이블 형식으로 데이터를 저장하고, 비관계형은 테이블 형식이 아닌 키-값(Key-Value) 형태로 값을 저장한다. 관계형 DBMS의 대표적인 예로는 MySQL, PostgreSQL, SQLite가 있고, 비관계형 DBMS로는 MongoDB, Redis 등이 있다.

RDBMS

**RDBMS(Relational DBMS)**는 1970년에 Codd가 12가지 규칙을 정의하여 만든 데이터베이스 모델이다. 행(Row)과 열(Column)의 집합으로 구성된 테이블의 묶음 형식으로 데이터를 관리하고, 테이블 형식의 데이터를 조작할 수 있는 관계 연산자를 제공한다. 실제로 구현된 RDBMS들이 12가지 규칙을 모두 따르지는 않았고, 최소한의 조건으로 앞의 두 조건을 만족하는 DBMS를 RDBMS라고 부르게 되었다.

학교라는 데이터베이스 안에 학생 명부, 출석부, 성적표, 생활기록부 등이 각각 테이블 형태로 관리되고, 각 테이블의 정보를 참조할 때는 학번이라는 고유 키를 사용한다. 아래처럼 학생 명부와 출석부가 독립된 테이블로 존재하지만, 학번을 통해 서로 연결된다.

20211235 오리 2016.01.01 070-8864-1337

SQL

RDBMS에서 관계 연산자는 **SQL(Structured Query Language)**이라는 쿼리 언어를 사용한다. SQL은 웹 애플리케이션이 DBMS와 상호작용할 때 사용하는 언어로, 사용 목적에 따라 크게 세 가지로 나뉜다.

**DDL(Data Definition Language)**은 데이터를 저장하기 위한 스키마나 데이터베이스 자체를 생성, 수정, 삭제하는 데 쓰인다.
**DML(Data Manipulation Language)**은 실제 데이터에 대해 조회, 저장, 수정, 삭제를 수행한다.
**DCL(Data Control Language)**은 데이터베이스 내 이용자의 접근 권한을 부여하거나 박탈하는 데 사용한다.

실제로 어떻게 쓰이는지 예시를 보면 흐름이 명확하게 보인다. 먼저 DDL로 데이터베이스와 테이블을 정의하고,

CREATE DATABASE Dreamhack;

USE Dreamhack;
CREATE TABLE Board(
    idx INT AUTO_INCREMENT,
    boardTitle VARCHAR(100) NOT NULL,
    boardContent VARCHAR(2000) NOT NULL,
    PRIMARY KEY(idx)
);

그 다음 DML로 데이터를 실제로 넣고, 조회하고, 수정한다.

-- 데이터 삽입
INSERT INTO Board(boardTitle, boardContent) VALUES('Hello', 'World!');

-- 데이터 조회
SELECT boardTitle, boardContent FROM Board WHERE idx=1;

-- 데이터 수정
UPDATE Board SET boardContent='DreamHack!' WHERE idx=1;

해시

데이터베이스에 사용자 정보를 저장할 때, 비밀번호를 그대로 저장하면 데이터베이스가 털렸을 때 모든 비밀번호가 그대로 노출된다. 이는 심각한 문제를 초래한다. 이 문제를 해결하기 위해 등장한 개념이 **해시(Hash)**다.

해시는 임의의 데이터를 고정된 길이의 값으로 변환하는 단방향 함수다. "hello"를 SHA-256으로 해시하면 항상 동일한 긴 문자열이 나오지만, 그 문자열을 보고 "hello"를 역으로 복원하는 것은 불가능하다. 입력값이 단 1글자만 바뀌어도 결과값이 완전히 달라지는 **눈사태 효과(Avalanche Effect)**도 특징이다. 이런 성질 때문에 비밀번호를 해시값으로 저장해두면, DB가 유출되더라도 원본 비밀번호를 알기 어렵다.

그런데 여기서 문제가 생긴다. 같은 비밀번호는 항상 같은 해시값을 만들어내기 때문에, 해커들은 미리 수많은 비밀번호의 해시값을 계산해 표로 만들어두고 대조하는 레인보우 테이블 공격을 사용한다. "123456"의 SHA-256 해시값은 전 세계 어디서나 동일하니까. 결국 빠르고 단순한 해시 알고리즘만으로는 비밀번호를 안전하게 보호하기 어렵다.

**브루트 포스(Brute Force)**는 가능한 모든 경우의 수를 하나씩 대입해보는 공격 방식이다. 비밀번호가 4자리 숫자라면 0000부터 9999까지 전부 시도해보는 식이다. 단순하지만 시간만 충분하다면 반드시 뚫리는 공격이라는 점에서 무시할 수 없다.
해시와의 관계에서 보면, 레인보우 테이블 공격이 미리 계산된 표를 가져다 대조하는 방식이라면, 브루트 포스는 실시간으로 모든 조합을 직접 해시해서 비교하는 방식이다. SHA-256처럼 연산 속도가 빠른 알고리즘은 현대 GPU를 활용하면 초당 수백억 번의 해시 연산이 가능하기 때문에, 짧거나 단순한 비밀번호는 브루트 포스에 순식간에 뚫린다.

bcrypt

이 문제를 해결하기 위해 등장한 것이 bcrypt다. 1999년 비밀번호 저장만을 위해 특별히 설계된 알고리즘으로, 두 가지 핵심 장치를 가지고 있다.

첫 번째는 **Salt(솔트)**다. 해시를 계산하기 전에 비밀번호에 랜덤한 고유값을 붙여버린다. 그러면 같은 "123456"이라도 사용자마다 전혀 다른 해시값이 만들어지기 때문에 레인보우 테이블 공격이 완전히 무력화된다.

두 번째는 **Cost Factor(비용 인수)**다. 내부적으로 해시 연산을 2의 n승만큼 반복하도록 설계되어 있어, 숫자를 높일수록 해시 생성이 느려진다. 사용자 입장에서는 로그인할 때 0.1~0.3초 정도의 차이에 불과하지만, 해커 입장에서는 수백만 번을 시도해야 하므로 그 차이가 엄청나다. 더 나아가 하드웨어가 발전할수록 이 값을 올려서 보안 수준을 유지할 수 있다는 것도 큰 장점이다.

이로 인해 해시 하나를 계산하는 데 의도적으로 시간이 걸리도록 설계되어 있기 때문에, 초당 시도할 수 있는 횟수가 SHA-256에 비해 수백만 배 이상 줄어든다. 공격자 입장에서 현실적으로 시도 자체가 불가능한 수준이 되는 것이다.

결과적으로 bcrypt가 저장하는 해시값에는 버전 정보, cost 값, salt, 실제 해시가 하나의 문자열에 모두 담겨 있어서 검증할 때도 별도의 정보 없이 비교가 가능하다.
